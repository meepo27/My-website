Real-Time Transaction Fraud Engine

Two-stage fraud scoring pipeline: XGBoost fast path (<10 ms) combined with a BiLSTM behavioural model for sequential anomaly detection — serving 1M+ daily card transactions at <50 ms p99 latency in production at Societe Generale.

Problem Statement

Card payment fraud decisions must be made within 100 ms of transaction initiation. The existing gradient-boosted model scored each transaction in isolation, missing fraud patterns that only emerge across a 20–30 transaction behavioural sequence. At the same time, a deep learning model alone couldn't meet the latency SLA.

The solution was a two-stage ensemble: a fast XGBoost scorer gates all transactions in under 10 ms; a BiLSTM runs only for elevated-risk transactions, adding sequential behavioural context without blowing the latency budget.

System Architecture

Kafka Transaction Stream → Redis Feature Cache → XGBoost (fast path, ~5ms) → BiLSTM + Attention (elevated risk) → Calibrated Ensemble → Accept / Flag / Block

Fast Path — XGBoost + Redis

Velocity and behaviour features (rolling 1 h / 24 h transaction counts, amount z-score, merchant category risk, geo-velocity, card-present flag) are pre-computed and cached in Redis with sub-millisecond lookups. The XGBoost model runs in ~5 ms and produces an initial risk score for every transaction.

Transactions scoring above a configurable threshold (~15% of volume) are routed to the deep path; all others receive a direct decision from XGBoost.

Deep Path — BiLSTM with Multi-Head Attention

The last 30 transactions for the account are fetched from Redis and scored by a bidirectional LSTM with 4-head attention (PyTorch, served via ONNX Runtime for 3× faster inference than native PyTorch). The attention mechanism weights the most suspicious moments in the sequence before the final dense classifier.

Ensemble & Decision Layer

Final risk score: 0.45 × XGBoost + 0.55 × BiLSTM — weights tuned on a stratified validation holdout via Optuna. Score is passed to the bank's FICO decision layer which applies business rules (spending limits, country embargoes) before the final accept / flag / block verdict.

MLOps & Monitoring

  • Both models retrained monthly on a rolling 90-day window; early-stopping prevents overfitting to stale patterns
  • A/B tested against the incumbent model for 4 weeks — 18% uplift confirmed before full traffic rollout
  • Feature drift monitored via Population Stability Index (PSI) alerts on Redis feature distributions
  • Model artefacts versioned in MLflow; deployment orchestrated via Azure ML pipelines
  • Real-time latency tracked in Datadog; p99 SLA alert at 80 ms
