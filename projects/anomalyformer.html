Problem Statement

An energy-sector client operated turbines and compressors instrumented with 32 sensor channels (vibration, temperature, pressure, RPM). Existing threshold alarms only triggered at the moment of failure — by which point equipment damage was already done.

Critically, the client had no labelled anomaly data: historical failures were rare, inconsistently recorded, and varied in type. A purely supervised approach was not viable. The system needed to learn normality and flag deviations — detecting failure precursors that no rule had previously defined.

System Architecture

SCADA / Sensor Stream → Apache Kafka → Spark Preprocessing → Patch-TST Transformer → Anomaly Scorer → Grafana SCADA Dashboard

Ingestion & Preprocessing

Raw sensor telemetry streams from 12 turbine units into Apache Kafka at 10 Hz. An Apache Spark streaming job performs per-sensor StandardScaling (fitted on the first 30-day normal baseline) and constructs 64-timestep sliding windows with 8-step stride. Feature metadata (sensor ID, unit ID, timestamp) is preserved for alert routing.

Patch-TST Transformer Model

Each 64-step multivariate window is divided into 8-step patches, linearly projected to 128-d embeddings, and processed by a 4-layer Transformer Encoder (pre-norm, 8 heads). A linear reconstruction head attempts to reproduce the original window from the encoded patches.

During training (normal data only, 90-day rolling window), the model minimises reconstruction MSE. At inference, per-timestep reconstruction error averaged across all 32 sensors becomes the anomaly score. Alerts fire when the score exceeds the 99th percentile of the training error distribution — giving a tunable false-alarm rate.

Serving & Monitoring

The trained Transformer is exported to ONNX and deployed on a Vertex AI custom serving endpoint. Anomaly scores stream back through Kafka into a Grafana dashboard integrated with the plant's SCADA system, giving operators real-time red/amber/green status per turbine unit.

The model is retrained quarterly by an automated pipeline triggered by a Vertex AI Pipelines DAG, using the most recent 90-day normal baseline to track seasonal operating changes.
