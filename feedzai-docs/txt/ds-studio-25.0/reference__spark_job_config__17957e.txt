##  `` SparkMasterURL `dataclass` Â¶
    
    
    SparkMasterURL(master: str, deploy_mode: str | None)
    

Stores information about the Spark master URL.

This class is useful to parse master URLs from Pulse Configuration, while maintaining compatibility with different Spark versions/distributions.

See more at [Submitting Applications / Master URLs](https://spark.apache.org/docs/3.3.1/submitting-applications.html#master-urls)

Attributes:

Name | Type | Description  
---|---|---  
`master` |  `str` |  Spark master URL. One of 'local', 'spark', 'mesos', 'yarn', or 'k8s'.  
`deploy_mode` |  `(str, optional)` |  Deploy mode for the different master URLs. One of 'client' or 'cluster'.

###  `` from_pulse_config `classmethod` Â¶
    
    
    from_pulse_config(config: Any) -> SparkMasterURL
    

Return the master URL compatible with Spark 2 onwards.

Previous URLs would be called local, yarn-client, yarn-cluster. However, Spark 2 introduced a "special" Spark master which is just YARN and delegates the deployment mode to Hadoop. The new options are::
    
    
    --master yarn --deploy-mode client|cluster
    

This function translates 'yarn-client' and 'yarn-cluster' to their respective Spark 2+ configs.

Parameters:

Name | Type | Description | Default  
---|---|---|---  
  
####  `config` Â¶

|  `SparkConfig` |  Spark Config as returned by :func:`get_spark_session_with_app_name` or :func:`get_spark_session_without_app_name`. |  _required_

##  `` get_spark_config_with_app_name Â¶

Retrieves the effective 'com.feedzai.pulse.service.datascience.config.SparkConfig' from Pulse Server to be used by an external Spark job. These configurations will depend on a given optional job profile and group model.

Name | Type | Description | Default  
---|---|---|---  
  
###  `pulse` Â¶

|  `[Server](../server/#ds_api.server.Server "            Server \(ds_api.Server\)")` |  The ds_api.Server used to communicate with Pulse. |  _required_  
  
###  `app_name` Â¶

|  `str` |  An optional name of a pulse application. This parameter should be used when we want to have access to application specific properties. This allows to use use the same properties being usd by Spark jobs executed in Pulse. |  _required_  
  
###  `job_profile_name` Â¶

|  `str` |  The name of the job profile to reuse the Spark properties defined there. If 'None' then it will retrieve the properties associated to default job profile for jobs of type 'EXTERNAL_DS_JOB'. |  `None`  
  
###  `group_name` Â¶

|  `str` |  The name of the group model used to retrieve the configurations defined in its properties. |  `None`  
  
###  `clean_spark_properties` Â¶
