###  `` auto_rename_metrics Â¶
    
    
    auto_rename_metrics()
    

Automatically renames all the metrics based on their configuration.

Default naming: `lowercase({groupby_fields}_{aggregation}_ {aggregation fields}_{window size}_{is_real_time})` eg. accountid_avg_amount_1h_rt. Advanced aggregations will be named: `lowercase({groupby_fields}_agg_ {window size}_{is_real_time})`. If a metric name is duplicated anywhere in the plan it appends "_n". Updates the references to the old names across the plan.

###  `` diff Â¶
    
    
    diff(other: Plan, show: bool = True, only_diff: bool = True, save: bool = False, save_as: Optional[str] = None) -> Optional[Plan]
    

Compare 2 plans. Differences can be displayed graphically when running inside a Jupyter Notebook.

Note

When creating a new plan from the diff, the schema and timestamp fields must be the in both plans. Also note that a renamed operator acts like a new operator for the diff, which means an operator that is not present in the 'other' plan will be discarded.

Danger

List and Sample operators are not supported.

####  `only_diff` Â¶

Notes

This method is intended to edit an existing Plan configuration previously exported.

General guidelines to edit the csv:

  * The row order of the 'operator_name' will determine their position in the Pulse Plan.
  * Pulse fields must be enclosed within the pattern ${field}.
  * Boolean values: {True, "TRUE", "True", "true", "T", "t", "1", 1} are accepted.
  * Any feature to be removed should be on a single row and the field 'map_remove_fields' should be True.
  * Feature updates will occur if a feature name is repeated.



Fields input format and considerations:

  * A more extensive documentation on each of the fields can be found on the Feature class docstrings.
  * operator_type: possible values are: map, metric, list, filter.
  * expression: to be used for Filter, Map and List operators.
  * metric_groupby_fields: formatted as a list of strings, eg. `['MerchantName', 'City']`.
  * metric_aggregation: Pulse fields must be enclosed within the pattern `'${field_desc}'`. eg. `'avg(${amount})'`, `'countDistinct(${MerchantCity})'`, `'count()'`.
  * metric_window_size: usual types "second", "minute", "hour", "day", "week". eg. 1 day.
  * metric_is_real_time: boolean.
  * metric_filter: Fields must be enclosed with the pattern `'${field}'` eg. `'${TransactionAmount} > 100 and ${Fraud} != false`'.
  * metric_delay: int.
  * metric_is_tumbling: boolean.
  * metric_filter_incomplete_instances: boolean, must be the same for the whole operator.
  * metric_timestamp_field: must be the same for the whole operator.
  * map_field_type: possible values are: numerical, string, datetime, categorical.
  * map_field_config: contains additional field configuration for datetime fields, possible values: nanoseconds, microseconds, milliseconds, seconds, minutes, hours, days. Or categories for categorical fields, eg. `['true', 'false']`.
  * map_remove_fields: boolean.
  * list_operation: get, or contains.
  * list_field: desc of the list field.



Returns:

`Plan` |  New Plan  
  
Raises:

Type | Description  
---|---  
`Exception` |  If the Plan configuration is invalid.

###  `` get_features_dependencies_by_type Â¶
    
    
    get_features_dependencies_by_type() -> Dict[str, Dict[str, Set[str]]]
    

Gets a set of feature dependencies calculated recursively.

Feature dependencies are represented as a unique tuple of feature name and operator name.

Considers the filter operator as a feature with dependencies.

If we have the following graph of dependencies for features A, B and C and specific dependency types:

[C]--(map)-->[B]--(aggregation)-->[A]

Feature C is considered an "aggregation" dependency of Feature A (regardless of its dependency type to B) because it is a dependency of the intermediate Feature B that is used in the aggregation expression of Feature A.

Returns:

Type | Description  
---|---  
`Dict[str, Dict[str, Set[str]]]` |  Dictionary of features' dependencies by type. The keys are the names of the features and the values are the dicts of upstream dependencies by type.
