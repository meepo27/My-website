Adds a new field to the schema.

Parameters:

Name | Type | Description | Default  
---|---|---|---  
  
####  `field` Â¶

|  `[FieldTemplate](../field/#ds_api.field.FieldTemplate "            FieldTemplate


  
      dataclass
   \(ds_api.field.FieldTemplate\)")` |  The new field, which is created according to the field template and added to the schema. |  _required_  
  
####  `index` Â¶

|  `int` |  The index of the new field in the Schema's list of fields. For example, if `index = 0`, the new schema will be added in the first position. If no index is specified, the field is appended to the end of the Schema. |  `None`  
  
Examples:
    
    
    >>> app = Feedzai().app(name="sample")
    >>> schema = app.pullSchemaByDesc(name="target-schema")
    >>> schema.add_field(field=FieldTemplate(
    ...     "numeric_field",
    ...     NativeType.FLOAT,
    ...     NumericalField())
    ... )
    >>> schema.add_field(field=
    ...     FieldTemplate("categorical_field",
    ...         NativeType.STRING,
    ...         CategoricalField({"value1", "value2"})
    ... ), index=0)

###  `` reorder_fields Â¶
    
    
    reorder_fields(order: tuple[int, ...])
    

Reorders the fields in the schema according to the specified list of indices. The new order is specified with a tuple of integers where each element is the index of the field in the original list of fields.

Parameters:

Name | Type | Description | Default  
---|---|---|---  
  
####  `order` Â¶

|  `tuple of int` |  Tuple with the field indices in the new order. |  _required_  
  
Raises:

Type | Description  
---|---  
`(ValueError, TypeError)` |  If the specified order is not valid.  
  
Examples:
    
    
    >>> app = Feedzai().app(name="sample")
    >>> schema = app.pullSchemaByDesc(name="four-field-schema")
    >>> schema.reorder_fields((1, 0, 2, 3))
    >>> schema.reorder_fields((3, 2, 1, 0))

##  `` get_internal_name Â¶
    
    
    get_internal_name(desc: str, schema: Schema | None = None) -> str
    

Return the internal (sanitized) name of a field.

This is a utility function to improve the UX of ds-api. Through ds_api the user should only care about the names as they appear in the UI ('desc').

Note

If a name is not found or the schema is not passed, this function acts as a no-op.

##  `` get_internal_names Â¶
    
    
    get_internal_names(names: _T, schema: Schema | None = None) -> _T
    

Return a sequence of internal (sanitized) names based on names as they appear in the UI.

Examples:
    
    
    >>> get_internal_names({"A Fancy Name here", "and another there"}, schema)
    {"a_fancy_name_here", "and_another_there"}
