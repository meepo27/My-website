# Signing in via SP-initiated

Was this page helpful?Â 

## Whyâ

SP-initiated is a use case of SSO that is supported by Pulse. A typical scenario of SP-initiated is when the user receives a URL by e-email or the user want to access a Feedzai product using a bookmark. E.g.:
    
    
    http://<BASE_PULSE_ADDRESS>/pulseviews/management/#apps/  
    

## How Toâ

For this example, two pulse instances have been [configured in the IdP as SPs](/pulse/latest/docs/common/pulse/administrators-guide/securing-an-environment/single-sign-on/configuring-ad-fs#add-a-relying-party-trust)

  * A Demo environment configured in the IdP as PULSE DEMO.
  * A Local environment configured in the IdP as PULSE.



SP applications

Note that the two Pulse instances are used here as an example. In a production system the IdP could be configured with any application used by the client.

To use the example of login to Pulse via SP-initiated, execute the following actions (assuming that you are not already signed in to the IdP):

  1. Access one of the URLs that have been configured as SP in the IdP. Note that you are redirected to the IdP URL to enter your credentials.

  2. Enter your SSO credencials to sign in. These user credentials should have been already [configured in the IdP](/pulse/latest/docs/common/pulse/administrators-guide/securing-an-environment/single-sign-on/configuring-ad-fs#add-new-users). As a result, you are redirected to the Pulse URL entered initially, i.e. to the internal path corresponding to the URL that you were trying to access on Step 1. Note that, if the user does not exist in the Pulse instance as a **Pulse User** , the user will be created automatically by user provisioning at the first sign in to the Pulse instance.

If you check the IdP URL you can verify that you are signed in:

  3. Access the other URL that has been configured as an SP. Note that, because you have already signed in to the IdP you have immediate access to this Pulse instance, as opposed to be redirected to the IdP webpage to enter again the credentials. However, the user authentication is still being performed between the SP and the IdP. Since this authentication occurs behind the scenes you might only notice in the title bar the URL flicking as a result of the internal authentication process (i.e. seamless login experience).

  4. Navigate to the  Administration tool.

  5. Open the Security view and select that you have signed in. Note that the fields are read-only because users that have SSO enable can only be created with the concept of user provisioning. User information previously configured in the IdP is mapped to the **Pulse User**. This information may contain **User** **Description** , Language, Groups, Roles, and **Tenants**.
