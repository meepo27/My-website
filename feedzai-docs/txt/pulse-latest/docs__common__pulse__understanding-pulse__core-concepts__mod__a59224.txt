# Feedzai Random Forest

Was this page helpful?Â 

Feedzai Random Forest (FZRF) is a machine learning algorithm developed by Feedzai. It is an enhanced variation of the [original Random Forest algorithm](https://www.stat.berkeley.edu/~breiman/randomforest2001.pdf).

Random forests use labeled data to learn its patterns. A random forest consists of a typically large number of decision trees, where each decision tree is a model. Each decision tree model is created by feeding each tree a random subset of the data (i.e. bagging).

In this topic you can learn about the parameters and the usage of Feedzai Random Forest.

**Feature selection function**|  The metric that defines how to pick the feature for the next split.| Information gain| Information gain: The next split will be the one that maximizes the information gain, i.e., that splits the two classes better. This means these feature selection functions give you a concrete number on how well you separated your two classes (e.g. fraud vs non-fraud) after a split. Your goal is to be able to separate the two classes as best as possible.|

### What is the condition for the nodes to be split?â

**What is the condition for the nodes to be split, is it ' <' goes left and '>=' goes right or '<=' goes left?**

It shouldn't make any difference if you are trying every split.

### Is bagging with or without repetition?â

Without repetition for each tree. With repetition "across trees", as shown in the figure below.

This means that a tree will never look at the same instance twice, but multiple trees in the same "forest" will most likely see overlapping instances.

### How do null values impact the computation of information gain, especially with categoricals?â

If you are trying to split on a categorical and an instance has a null in that field, you must count the instance for the total. Yet you shouldn't count it for the specific subset when calculating the information gain.

A few more notes regarding FZRF and null values:

  * FZRF will ignore any instance where the class label is missing. This means that the whole instance is dropped during training.
  * FZRF will use instances where the features have missing values up to the first split using that feature (i.e. for each tree/branch).



The consequence of the last point is that when a feature with very high number of missing values is being tested for splitting, it may **have very high information gain**. This will lead the model to select the feature, hence dropping most of the instances in the training data.

### Is the data replicated into memory for each tree due to bagging?â

Yes, because trees are trained in parallel and each in-bag dataset is a partition of the initial data.
