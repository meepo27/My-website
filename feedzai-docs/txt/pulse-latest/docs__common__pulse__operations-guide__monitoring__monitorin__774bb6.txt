# Monitoring the Persistence of Events in the Workflow

Was this page helpful?Â 

When your Application is published with one or more workflows executing, there are various storages to which events' data can be persisted.

The following sections detail the metrics available for each one of them.

## Workflow Event Storageâ

Each Workflow has 1 connector to the event storage (either to a relational or Cassandra database), used for storing events near the end of processing and to recover via replay.

Name | Description | Unit | Tags  
---|---|---|---  
Counters  
      
    
    pulse.workflow.eventstorage.eventsQueuedSize

| The number of events pending in-memory to be persisted to the storage. | # | _workflowID  
appSlug  
metricType  
appType_  
  
##### Example of live metricsâ
    
    
    "pulse.workflow.eventstorage.eventsQueuedSize,appSlug=nank,metricType=APPLICATION,appType=PULSE_APPLICATION,workflowID=pBqsDBqu114nuQhbTKlPjw":{  
        "value":92  
    }
