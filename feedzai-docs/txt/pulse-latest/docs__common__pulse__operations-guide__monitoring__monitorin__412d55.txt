# Monitoring Cassandra Driver Sessions

Was this page helpful?Â 

Multiple Pulse components can be configured to work with a Cassandra database, such as the Profile Store and the Event Storage. The `/metrics` API exposes several metrics that allow Pulse operators to monitor the Cassandra drivers that these different components use to communicate with the Cassandra cluster(s).

This page describes how to configure the monitoring of these drivers, as well as the available metrics.

## Cassandra drivers and their configuration propertiesâ

Within a Pulse App Engine, several Cassandra drivers can be created depending on the defined configurations. If a Cassandra connection configuration is provided at the global level, a Cassandra driver may be created at the App Engine level, which can then be used by the multiple components within the App Engine, as long as the Cassandra connection configuration of these components is either not provided (defaults to global) or equal to the one defined at the global scope. Otherwise, the component itself will create its own Cassandra driver.

The prefix of the Cassandra driver metric names, as well as the metric tags, changes depending on whether the driver is created by the App Engine or by a specific component within the App Engine:

---|---|---

| For the Cassandra driver that can be created by the App Engine. | _appSlug

## Available metricsâ

The following table lists all the metrics that are exposed for each Cassandra driver:

Name | Description | Unit  
---|---|---  
Counters  
      
    
    <prefix>.blocking-executor-queue-depth

| The total number of queued-up tasks in the Cassandra driver's blocking executor. | #  
      
    
    <prefix>.connect-to

| The total number of Cassandra hosts the driver is currently connected to. | #  
      
    
    <prefix>.executor-queue-depth

| The total number of queued-up tasks in the Cassandra driver's main internal executor. | #  
      
    
    <prefix>.inflight-requests

| The total number of inflight requests to Cassandra hosts. | #  
      
    
    <prefix>.known-hosts

| The total number of Cassandra hosts currently known by the driver, regardless of whether the hosts are up or down. | #  
      
    
    <prefix>.open-connections

| The total number of currently open connections to Cassandra hosts. | #  
      
    
    <prefix>.reconnection-scheduler-task-count

| The total number of queued up tasks in the Cassandra driver's reconnection executor. | #  
      
    
    <prefix>.request-queue-depth

| The total number of enqueued requests on all Cassandra hosts. | #  
      
    
    <prefix>.task-scheduler-task-count

| The total number of queued-up tasks in the Cassandra driver's scheduled tasks executor. | #  
      
    
    <prefix>.trashed-connections

| The total number of currently trashed connections to Cassandra hosts. | #  
Gauges  
      
    
    <prefix>.authentication-errors

| The number of authentication errors while connecting to Cassandra nodes. | #  
      
    
    <prefix>.client-timeouts

| The number of requests that timed out before the driver received a response. | #  
      
    
    <prefix>.connection-errors

| The number of errors while connecting to Cassandra nodes. | #  
      
    
    <prefix>.ignores

| The number of times a request was ignored due to the retry policy, for instance, due to timeouts or unavailability. | #  
      
    
    <prefix>.ignores-on-client-timeout

| The number of times a request was ignored due to the retry policy after a client timeout. | #  
      
    
    <prefix>.ignores-on-connection-error

| The number of times a request was ignored due to the retry policy after a connection error. | #  
      
    
    <prefix>.ignores-on-other-errors

| The number of times a request was ignored due to the retry policy after an unexpected error. | #  
      
    
    <prefix>.ignores-on-read-timeout

| The number of times a request was ignored due to the retry policy after a read timed out. | #  
      
    
    <prefix>.ignores-on-unavailable

| The number of times a request was ignored due to the retry policy after an unavailable exception. | #  
      
    
    <prefix>.ignores-on-write-timeout

| The number of times a request was ignored due to the retry policy after a write timed out. | #  
      
    
    <prefix>.other-errors

| The number of requests that returned errors not accounted for by another metric. | #  
      
    
    <prefix>.read-timeouts

| The number of read requests that returned a timeout (independently of the final decision taken by the retry policy). | #  
      
    
    <prefix>.retries

| The number of times a request was retried due to the retry policy. | #  
      
    
    <prefix>.retries-on-client-timeout

| The number of times a request was retried due to the retry policy after a client timeout. | #  
      
    
    <prefix>.retries-on-connection-error

| The number of times a request was retried due to the retry policy after a connection error. | #  
      
    
    <prefix>.retries-on-other-errors

| The number of times a request was retried due to the retry policy after an unexpected error. | #  
      
    
    <prefix>.retries-on-read-timeout

| The number of times a request was retried due to the retry policy after a read timed out. | #  
      
    
    <prefix>.retries-on-unavailable

| The number of times a request was retried due to the retry policy after an unavailable exception. | #  
      
    
    <prefix>.retries-on-write-timeout

| The number of times a request was retried due to the retry policy after a write timed out. | #  
      
    
    <prefix>.speculative-executions

| The number of times a speculative execution was started because a previous execution did not complete within the delay specified by speculative execution policy. | #  
      
    
    <prefix>.unavailables

| The number of requests that returned an unavailable exception (independently of the final decision taken by the retry policy). | #  
      
    
    <prefix>.write-timeouts

| Returns the number of write requests that returned a timeout (independently of the final decision taken by the retry policy). | #  
Meters  
      
    
    <prefix>.bytes-received

| The number of bytes received by the Cassandra driver so far. | #  
      
    
    <prefix>.bytes-sent

| The number of bytes sent by the Cassandra driver so far. | #  
Timers  
Metrics regarding the number of user requests performed on the Cassandra cluster: 

  * The total number of requests.
  * The requests rate (in requests per second), including 1, 5 and 15-minute rates.
  * The mean, min and max latencies, as well as latency at a given percentile.

|
