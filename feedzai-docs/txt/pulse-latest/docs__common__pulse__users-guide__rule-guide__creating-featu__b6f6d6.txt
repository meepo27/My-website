# Handling NULL Values with PQL

Was this page helpful?Â 

NULL is a special value that represents the absence of a valid value. Any operation that acts on it as if it was a valid value fails with a NullPointerException. Untreated datasets might contain NULL values, and so they are potentially unsafe for any activity within Pulse. This topic describes how to make datasets more robust by handling NULL values using PQL expressions.

## Replacing NULL valuesâ

One of the common ways to handle NULLs is to replace them with a value that fits into the data field's type. It's common to pick the substitute value so that it doesn't represent a meaningful value for that data field. For instance, a NULL in the transaction amount field could be replaced by 0. To accomplish this replacement, you can use the **coalesce operator** (`??`) in a map operator or metric operator.

Usage of the ?? operator:
    
    
    <good-case-value> ?? <null-case-value>  
    

This expression returns `<good-case-value>`, unless `<good-case-value>` is NULL. If `<good-case-value>` is NULL, the expression returns `<null-case-value>`.

### Nullable typesâ

Untreated input fields can contain NULL values. Hence, PQL treats every input field as a nullable type, meaning a type that can contain NULL values in addition to an original data type.

This fact is marked with a ? in the data type name.

For example, the _Amount_ field is not of _double_ type, but of _double?_ , meaning a type that contains all double values plus the NULL.

When using both nullable and non-nullable types in an [arithmetic operator](/pulse/latest/docs/common/pulse/users-guide/rule-guide/creating-features/using-pql-in-features/operators-in-pql) or in a [function](/pulse/latest/docs/common/pulse/users-guide/rule-guide/creating-features/using-pql-in-features/function-calls-in-pql) that returns a numeric value, the resulting data type is nullable.
