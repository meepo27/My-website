# Monitoring Event Storage Dumps in Pulse

Was this page helpful?Â 

This page describes how to monitor the dumping of events when they fail to be written to the Event Storage in Pulse using the `/metrics` endpoint.

## Introductionâ

In Pulse, each Workflow has it own Event Storage. When events reach the end of the workflow they are persisted in the Event Storage. If the Event Storage isn't avaliable (e.g.: Database is offline) the events are dumped to disk and are reprocessed later on by the Event Storage Dump component.

It is essential to know if this component is operating within reasonable limits. By taking monitoring metrics from the Event Storage Dump, Pulse operators can have access to different information related to event dumps operations via the `/metrics` endpoint.

info

To enable the component that reports this metrics, reach out to the Feedzai Customer Success (CS) team.

## Metricsâ

The metrics are associated with an application, identifiable via an `appSlug` tag, where the service is running.

The `appType` and `metricType` tags, that are also associated with these monitoring metrics, are common to other metrics exposed in Pulse and App Engines. They inform where the metrics were collected (Pulse Server or App Engine) and what type of metric it is being reported (e.g. APPLICATION), respectively.
