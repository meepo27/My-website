# Function Calls in PQL

Was this page helpful?Â 

Function calls allow you to execute predefined functions on current values. There are two types of functions that can be called:

  * Built-in functions of Pulse
  * User-Defined Functions (UDFs) â a set of additional functions bundled with Pulse



This topic gives an overview of the possible function calls, and points you to the right topics to learn more.

Container functions in `Map` and `Metrics` operators

Functions that operate on collections (like `List`s, `Set`s or `Map`s) are not supported in the PQL fields of [Map Operators or Metric Operators](/pulse/latest/docs/common/pulse/understanding-pulse/core-concepts/plans/operators-reference).

For example, using `contains` or `indexOf` on collections in PQL fields of such operators will result in an error.

The recommended alternative is to use UDFs (User Defined Functions) instead of these built-in functions.

## UDF callsâ

Pulse comes with a set of [User-Defined Functions (UDFs)](/pulse/latest/docs/common/pulse/understanding-pulse/core-concepts/user-defined-functions) that can be used in addition to the built-in functions.

UDFs in Metrics

When using UDFs in metric filters and aggregations, UDFs receive fields from a single event and not from a collection of events.

You can use the following syntax to call a UDF:
    
    
    <class_name>.<function_name> ( <arguments> )  
    

For example, to concatenate two strings:
    
    
    Strings.strcat("One", "Two") // Returns "OneTwo"  
    

java regex syntax

Pulse uses the Java regex flavor for UDFs, which means that all regular expressions must conform to the syntax and rules of Java's `java.util.regex.Pattern` class.

According to the usual regex syntax, when you need to match a literal special character that has meaning in regex (e.g. `*`, `+`, `?`, `.`), you must escape it using a backslash (`\`) within the regex pattern (e.g. `\*`, `\+`, and so on).

However, because the regex pattern itself is often passed as a Java String literal, the backslash (`\`) used for escaping the regex special character must itself be escaped according to Java String rules.

Therefore, to include an escaped character like `\*` (match literal asterisk) in a regular expression defined as a Java string, you must write it as `\\*`.
